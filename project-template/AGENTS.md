# AGENTS.md

本文件是影刀 xbot / 编码版项目的 Agent 规则。

核心目标：**最小改动、简单直接、不猜 API、不做无关重构。**

## 0. 开始任务前

1. 用户当前需求优先。
2. 当前项目已有代码和现有风格优先。
3. 知识库固定路径为 `C:\Users\Administrator\Desktop\影刀xAI开发指南`。
4. 开始任务时先确认知识库目录存在。若不存在，立即停止并请用户补充正确路径；不要猜测其他目录，也不要继续开发。
5. 先检查真实项目现有代码。仅当新增或无法确认 xbot API、市场指令、页面行为时，再按知识库中的 `llms.txt` 定位相关文档。

## 1. 默认执行原则

1. 目标清楚时直接改，不要先写长计划。
2. 只解决当前任务明确要求的问题。
3. 只改与当前需求直接相关的文件、函数和代码行。
4. 不做无关重构、无关格式化、无关改名或结构重排。
5. 能用现有结构解决，就不要新增框架、管理器、抽象层或复杂配置。
6. 发现无关潜在问题可以指出，但不要擅自修改。
7. 每一处改动都必须能对应当前需求。

## 2. 复杂任务处理

只有新增完整功能、跨多个模块、涉及高风险写入，或用户明确要求先评审、设计、规划时，才先给简短计划。

复杂任务仍只做必要步骤：

1. 先看当前项目已有代码。
2. 只搜索与当前目标直接相关的文件和调用。
3. 优先在现有结构内完成，不默认重构架构。
4. 不确定 API、页面行为、XPath、市场指令参数时，标注“需运行验证”。

## 3. 代码风格

1. 代码要简单、直接、容易阅读。
2. 主入口优先采用从上到下连续阅读的顺序式流程，使执行顺序、数据流和关键状态可以直接看清。
3. 简单功能优先使用普通变量、`if`、`for`、`try` 等直白写法，不使用嵌套推导式、`lambda`、装饰器、生成器、动态调度或难以理解的一行式写法。
4. 不要为了减少行数而压缩语句或制造跳转。
5. 保持项目现有风格，不要为了“更规范”强行重构。
6. 变量名要直白，避免含义模糊的命名。
7. 默认使用标准库；新增第三方依赖需要用户明确允许，或项目已在使用。
8. 关键业务判断可以写中文注释；显而易见的逻辑不要写注释。

## 4. 函数与结构

1. 除非代码量较多，否则只被调用一次的代码直接写在调用处，不封装函数。
2. 单次调用逻辑只有在代码较多、能形成清晰独立的业务步骤，并且抽出后更利于自上而下阅读时，才允许封装函数。
3. 函数体只有一两行时，不要封装。
4. 抽函数后参数更多、状态传递更多或阅读更绕时，不要抽。
5. 明显重复、需要多处复用，或项目已有同类结构时，可以抽函数。
6. 默认不要新增类、管理器、工厂函数、复杂配置层或抽象层。
7. 不为未来可能出现的需求预留未使用参数、接口、分支、配置、Hook、兼容层或扩展点。
8. 是否拆模块以用户需求、现有结构、业务边界和实际代码量为准，不单纯按文件长度决定。

## 5. 输入与异常

1. 影刀项目入口通常为 `main(args)`。
2. 已知 `args` 参数名时，严格按已有参数名使用。
3. 不要同时兼容多个猜测参数名。
4. 输入形态不确定时，只在边界统一归一化一次。
5. 异常处理只覆盖当前业务明确需要处理的失败情况。
6. 捕获异常时必须保留关键错误信息，不要静默吞异常。
7. 清理、关闭、停止监听等收尾失败，至少记录 `warning`。

## 6. 影刀日志与页面自动化

1. 影刀项目禁止使用 Python 标准 `logging`，只使用 `from xbot.app import logging`。
2. 日志方法只传一个字符串参数，动态内容使用 f-string。
3. 需要异常堆栈时，用 `traceback.format_exc()` 拼到 `logging.error(...)`。
4. 涉及浏览器、URL、页面业务时，优先使用 `xbot.web` 和浏览器对象能力。
5. 除非用户明确要求接口方式，或项目已有接口调用方式，否则不要用 `requests`、`httpx`、`aiohttp`、`urllib` 处理网页业务。
6. 能用元素、选择器、页面接口处理，就不要优先坐标点击。
7. XPath、CSS、页面接口、按钮状态未验证时，必须标注“需运行验证”。

## 7. 修改、验证与影刀同步

1. 修改已有文件前先阅读相关上下文，避免覆盖用户已有改动。
2. 做最小 diff，不执行会丢改动的命令。
3. 默认不新增测试，不默认运行完整测试；按风险做最小必要验证。
4. `shadowbot_sync_tool.py` 位于项目根目录，与 `package.json` 同级。
5. 项目新增文件后，运行 `python shadowbot_sync_tool.py prepare`；仅修改已有文件且用户未要求同步时不运行。
6. 用户说“同步影刀”“执行影刀同步”“同步到影刀”或同类表述时，均指执行 `python shadowbot_sync_tool.py prepare`，即使只修改了已有文件也要执行。
7. “同步影刀”不等于 Git 提交、Git push 或普通文件复制，不要用其他操作替代同步脚本。
8. 同步完成不等于已在影刀编辑器内验证通过。
9. 未运行测试或同步时，最终回复必须明确说明。

## 8. 禁止行为

1. 无关重构、无关格式化、无关改名。
2. 擅自更换实现路线。
3. 引入不必要依赖、复杂封装或复杂配置系统。
4. 为低概率场景写大量防御代码。
5. 基于旧项目经验猜 API、命令、目录、XPath、页面字段或市场指令参数。
6. 提交账号、密码、token、webhook 或其他敏感信息。
7. 把“需运行验证”的内容描述成“已经验证通过”。

## 9. 最终回复

完成后简短说明：修改文件、核心改动、验证与同步情况、仍需运行验证的内容。
