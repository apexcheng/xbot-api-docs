# 市场指令排查与返回结构边界

本文沉淀影刀市场指令在编码版调用时的排查顺序和踩坑边界，不替代 `xbot-api-docs/docs/debug/market-extension-source.md`、`xbot-api-docs/docs/extension-instructions.md` 总入口和 `xbot-api-docs/docs/extensions/` 拆分页说明。

## 1. 适用场景

遇到以下情况，优先按本文思路排查：

- 市场指令文档只写参数名，没写真实可选值。
- 可视化流程能运行，但编码版调用不生效。
- 下拉选项不知道应该传中文、英文还是内部枚举值。
- 指令不报错，但行为和预期不一致。
- 怀疑包装层和底层实现不一致。
- 需要确认返回值结构、异常返回形态或异步副作用。

## 2. 最稳排查路径

```text
确认模块能导入
    -> inspect.signature() 看外层签名
    -> inspect.getfile() 定位安装目录
    -> 进入当前项目 xbot_extensions
    -> 查看 __init__.py / _core.py / core.py / 业务 .py
    -> 确认真实参数值、默认值、分支判断和返回结构
```

重点：`__init__.py` 可能只是包装层，不一定包含真实业务逻辑。

## 3. 不要用界面中文猜编码版参数

- 可视化界面显示的中文选项，不一定是编码版真实参数。
- 如果源码判断 `close_type == "click"`，编码版就传 `"click"`，不是 `"点击"`。
- 确认枚举值前，不要在业务代码里反复试多个候选值做兜底。

## 4. 返回结构按单个指令确认

- 不要预设所有市场指令都返回 `dict`、`list` 或固定对象。
- 封装某个指令前，先通过文档、源码或运行结果确认返回结构，再决定是否取 `data`、是否做类型校验、失败时如何处理。
- 钉钉 AI 表格指令按 `data.records` 取记录，是该指令的已验证约定，不应泛化到所有市场指令。

## 5. 钉钉 AI 表格已验证约定

- 记录列表默认从 `result.get("data", {}).get("records")` 取。
- 单条记录字段默认按 `record["fields"]` 取。
- 多选或选项字段常见结构为 `{"name": "...", "id": "..."}`，显示值取 `.get("name")`。
- 开发前仍需用真实返回数据确认字段结构，不要只凭历史经验假设。

## 6. 不提交内部源码

- 本仓库只记录排查方法、参数结论和调用示例。
- 不要把影刀运行包源码、反编译源码、第三方市场指令完整源码、账号、token、Cookie 写进仓库。
- 需要记录源码结论时，只写最小必要判断逻辑、适用范围和验证方式。

## 7. 结论沉淀位置

- 已确认且稳定的 API 或参数说明，回写到 `xbot-api-docs/docs/`。
- 跨指令通用排查经验，写到本文。
- 历史错误结论，写到 `wiki/error-book.md`。
- 尚未验证的参数、返回结构或行为差异，写到 `wiki/unresolved.md` 并标注“需运行验证”。
