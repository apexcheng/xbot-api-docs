# 使用 Claude Code、Codex 开发影刀 xbot：AI Agent 工作流

本文说明如何将 AI 编程 Agent 用于影刀编码版、xbot 和 RPA 自动化项目，同时降低误改代码、猜测 API、遗漏验证和上下文污染的风险。

适用工具包括：

- Claude Code
- OpenAI Codex
- Cursor
- 其他能够读取仓库文件、执行命令并修改代码的 AI Agent

## 核心思路

AI Agent 不应只收到一句“帮我写一个影刀流程”。更稳定的做法是同时提供：

1. 真实业务目标
2. 真实影刀项目目录
3. 本知识库目录
4. 输入、输出和验收标准
5. 当前人工操作流程
6. 相关页面、表格、文件或接口信息
7. 允许修改和禁止修改的范围

## 推荐上下文结构

```text
业务需求
├── 目标与验收标准
├── 输入数据
├── 输出结果
├── 人工确认点
├── 异常处理要求
└── 已知限制

开发上下文
├── 真实影刀项目目录
├── yingdao-xbot-ai-agent 知识库
├── AGENTS.md
├── llms.txt
├── 标准流程项目参考（仅同类报表项目）
├── 相关 xbot API 文档
└── 现有项目代码
```

## 推荐执行流程

### 1. 明确目标

将需求改写成可以验证的结果。例如：

```text
目标：读取指定 Excel 文件中的订单号，逐行打开网页查询状态，并把结果写回原表。

验收标准：
- 能读取指定 Sheet
- 能跳过空订单号
- 每个订单只查询一次
- 查询结果写入指定列
- 页面异常时记录错误，不覆盖原数据
- 在影刀编辑器中完成一次实际运行验证
```

### 2. 确认两个目录

向 Agent 明确区分：

```text
知识库目录：固定为 C:\Users\Administrator\Desktop\影刀xAI开发指南，用于查规则、API、示例和排错资料
真实项目目录：用于修改实际运行代码
```

这是影刀 Agent 开发中最重要的上下文之一。

### 3. 读取稳定规则

Agent 应先读：

- [`AGENTS.md`](../AGENTS.md)
- 真实项目中的规则文件
- 真实项目现有代码和业务说明

仅当新增或无法确认 xbot API、市场指令、页面行为时，再按 [`llms.txt`](../llms.txt) 定位相关技术文档。

不要一次性把全部文档塞入上下文。应根据任务逐步读取，以减少无关信息干扰。

### 4. 先调查，再修改

建议让 Agent 在实施前回答：

- 当前功能在哪个文件和函数中实现
- 现有输入输出是什么
- 哪些代码与需求直接相关
- 计划修改哪些文件
- 如何验证结果
- 是否存在尚未确认的 API 用法

复杂任务应写入 `TASK.md`；简单任务可以直接修改，但仍应先定位现有实现。

### 5. 同类报表项目参考

仅在新建或重构以下项目时，读取 [标准流程项目参考](standard-project-reference.md)：

- 多个网页或平台数据源依次下载
- 多个模块写入同一个目标工作簿
- 任一模块失败时不能保存部分结果
- 需要完整流程重试、统一保存和统一通知

具体结构、适用范围和参考边界统一以该文档为准。其他类型的影刀项目不要强行套用。

### 6. 使用最小改动

对现有影刀项目进行“外科手术式修改”：

- 不重构无关代码
- 不替换现有日志体系
- 不改变无关变量名和格式
- 不添加当前需求不需要的抽象层
- 不因为“更优雅”而扩大修改范围

#### 保持主流程清晰

影刀 RPA 项目通常以业务步骤为核心，主入口应尽量按照真实执行顺序排列：

```text
读取参数
→ 判断是否需要更新
→ 下载数据
→ 写入表格
→ 处理业务规则
→ 保存
→ 发送通知
```

默认保持主流程清晰；是否拆模块以用户需求、现有结构和业务边界为准，不单纯按文件长度决定。

### 7. 验证 API 依据

Agent 使用 xbot API 时，应先检查真实项目现有代码。仅当新增或无法确认 xbot API、市场指令、页面行为时，再按以下顺序确认：

1. 查 [`llms.txt`](../llms.txt) 中的文档入口
2. 查 `xbot-api-docs/docs/` 对应页面
3. 查仓库现有示例
4. 涉及市场指令时查扩展源码或参数映射
5. 无法确认时明确标记为待验证

不要用 Selenium、Playwright、pywin32 或 openpyxl 的经验直接推断 xbot API 参数。

## 可直接使用的提示词模板

```text
请在真实影刀项目中完成以下任务。

知识库目录：C:\Users\Administrator\Desktop\影刀xAI开发指南
真实项目目录：C:\path\to\shadowbot-project

任务目标：
[填写目标]

验收标准：
- [标准 1]
- [标准 2]

执行要求：
1. 先读取真实项目根目录中的 AGENTS.md，并确认固定知识库路径存在；不存在就停止并要求用户补充。
2. 再读取真实项目现有代码，定位当前实现。
3. 新建或重构多数据源报表流程时，先读取 docs/standard-project-reference.md，并优先参考其结构。
4. 只修改与当前需求直接相关的内容。
5. 默认保持主流程清晰；是否拆模块以用户需求、现有结构和业务边界为准，不单纯按文件长度决定。
6. 仅当新增或无法确认 xbot API、市场指令、页面行为时，再按 llms.txt 定位相关文档。
7. 复杂任务先更新 TASK.md；简单任务直接修改。
8. 修改后执行必要测试。
9. 最后说明实际改动、验证结果、尚未验证内容和风险。
```

## 复杂任务的阶段拆分

### 阶段 1：调查

输出：

- 项目结构
- 当前实现位置
- 依赖的页面、文件、表格、全局变量或市场指令
- 已知风险

### 阶段 2：方案

输出：

- 最小修改方案
- 修改文件列表
- 每一步的验证点
- 需要人工确认的地方

### 阶段 3：实现

要求：

- 按计划逐步修改
- 每个阶段更新进度
- 发现原假设错误时及时修正方案

### 阶段 4：验证

至少检查：

- 语法和导入是否正常
- 关键分支是否覆盖
- 页面或表格对象是否与实际环境一致
- 错误处理是否符合业务要求
- 影刀内实际运行是否通过

## 常见失败方式

### Agent 在错误目录修改

症状：代码改了，但影刀应用没有变化。

处理：确认修改的是实际应用目录，并回到影刀编辑器内重新加载和验证。

### Agent 猜测 API

症状：函数名看似合理，但运行时报参数错误、对象不存在或返回值结构错误。

处理：回到对应 API 文档、示例或市场指令源码验证。

### Agent 过度重构

症状：一个小需求引发多个文件重写，难以判断问题来自哪里。

处理：恢复到最小修改范围，只保留需求必需改动。

### 上下文过多

症状：Agent 混用不相关 API、忽略当前项目规则或重复生成已有功能。

处理：只加载当前任务相关文档，并通过 `llms.txt` 按需导航。

### 只做静态检查，没有实际验证

症状：代码语法正常，但影刀运行环境、元素库、市场指令或 WPS 行为不一致。

处理：明确区分静态检查和影刀环境运行验证。

## 完成报告建议格式

```md
## 实际改动

- 修改文件：...
- 修改内容：...

## 验证结果

- 静态检查：通过 / 未通过
- 本地测试：通过 / 未执行
- 影刀内运行：通过 / 未执行

## 未验证事项

- ...

## 风险

- ...
```
