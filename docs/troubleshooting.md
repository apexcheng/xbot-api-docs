# 影刀编码版开发排错指南：xbot、RPA、市场指令与 AI Agent

本文提供影刀 xbot 项目的通用排错顺序，适用于浏览器自动化、Excel / WPS、Windows 桌面操作、市场指令、钉钉 AI 表格和 AI Agent 生成代码等场景。

## 排错原则

### 先保留完整错误

至少记录：

- 完整异常文本
- 触发时间
- 运行到哪个步骤
- 输入参数
- 返回值或响应体
- 相关文件和函数
- 当前影刀、浏览器、Excel / WPS 环境
- 是否可以稳定复现

不要只保留“运行失败”或最后一行错误。

### 先复现，再修改

修复前先确认：

- 是否每次都出现
- 哪个最小输入可以触发
- 是代码问题、数据问题还是环境问题
- 旧版本是否也会出现

无法稳定复现时，应明确说明，不要把猜测写成确定结论。

### 一次只验证一个假设

例如怀疑 filter、字段类型和网络异常时，不要同时修改多个参数。应分别验证，避免成功后无法判断真正原因。

## 通用排错流程

```text
收集完整错误
    ↓
构造最小复现
    ↓
确认真实项目和运行环境
    ↓
定位文件、函数和输入
    ↓
查对应 xbot API 文档
    ↓
检查现有代码与示例
    ↓
必要时检查市场指令源码
    ↓
做最小修复
    ↓
影刀内重新验证
    ↓
记录正确结论和错误结论
```

## 先判断问题属于哪一层

### 业务输入层

常见问题：

- 空值
- 字段名称错误
- Sheet 名称错误
- 长数字精度丢失
- 日期或文本格式不一致
- 重复数据
- 文件路径错误

### xbot API 调用层

常见问题：

- 函数或对象使用错误
- 参数名称、类型或层级错误
- 返回值结构理解错误
- 对象来源不正确
- 把其他 Python 库用法套到 xbot

### 页面或应用环境层

常见问题：

- 未登录
- 验证码或风控
- 页面结构变化
- iframe
- 元素被遮挡
- Excel / WPS 进程异常
- 文件被占用
- Windows 窗口状态不同

### 市场指令或第三方接口层

常见问题：

- 可视化参数和编码版参数映射不同
- 市场指令版本变化
- 请求体结构不符合接口要求
- 服务端返回 500、限流或未知错误
- 文档与实际实现不一致

### Agent 上下文层

常见问题：

- Agent 修改了错误目录
- 没有读取 `AGENTS.md`
- 使用了过期资料
- 同时加载太多不相关文档
- 将推测当成已验证 API
- 扩大修改范围导致新问题

## 浏览器自动化排错

入口：

- [浏览器自动化指南](browser-automation.md)
- [xbot 浏览器文档](../xbot-api-docs/docs/browser.md)
- [iframe2 扩展](../xbot-api-docs/docs/iframe2-extension.md)

检查顺序：

1. 当前页面 URL 是否正确
2. 是否已登录
3. 是否出现验证码、风控或异常页
4. 元素是否位于 iframe
5. 定位方式是否依赖随机 class
6. 元素是否已出现并可点击
7. 是否滚动了正确容器
8. 点击后是否等待了异步加载
9. 页面结构是否已变化

## Excel / WPS 排错

入口：

- [Excel / WPS 自动化指南](excel-automation.md)
- [xbot Excel 文档](../xbot-api-docs/docs/excel.md)

检查顺序：

1. 文件路径是否真实存在
2. 当前打开的是不是目标工作簿
3. Sheet 名称是否完全一致
4. 表头行和数据开始行是否正确
5. 列索引是否错位
6. 长数字是否被转换或丢失精度
7. 文件是否被占用
8. Excel / WPS 进程是否正常
9. 保存路径和权限是否正确

## 市场指令排错

当出现以下情况时，应检查市场指令源码或参数映射：

- 可视化流程能运行，编码版调用失败
- 参数文档不完整
- 函数只返回笼统的 unknownError
- 市场指令升级后行为变化
- 同一参数在 UI 和代码中结构不同

参考：

- [市场指令扩展开发](../xbot-api-docs/docs/extension-instructions.md)
- [市场指令源码排查](../xbot-api-docs/docs/debug/market-extension-source.md)

建议记录：

- 市场指令名称和版本
- 可视化界面中填写的值
- 编码版实际传入结构
- 扩展源码中的真实参数名
- 最小可运行调用
- 失败和成功请求的差异

## 钉钉 AI 表格异常

入口：

- [钉钉 AI 表格文档](../xbot-api-docs/docs/extensions/activity-5b77c4ce.md)

遇到 `HTTP 500 unknownError`、filter 查询失败或记录分页异常时，建议依次检查：

1. base、sheet 和字段是否正确
2. filter 是否放在接口要求的层级
3. `combination`、`conditions`、`field`、`operator` 和 `value` 结构是否正确
4. 字段类型与 value 类型是否匹配
5. 单条件是否成功
6. 多条件逐个增加后在哪一步失败
7. 更换不同订单号后结果是否一致
8. 无 filter 的分页调用是否成功
9. 服务端 request id 是否已记录

不要仅凭订单号很长就判断查询失败。应以实际请求结构、字段类型和多组输入测试结果为依据。

## HTTP 500 与 unknownError

服务端 500 不一定代表本地代码完全正确，也不一定代表服务端永久故障。需要同时确认：

- 请求参数是否符合接口真实格式
- 是否存在空字段或非法字段名
- 数组和字符串类型是否匹配
- 请求体是否多包或少包了一层
- 是否只有特定输入触发
- 是否可通过最小请求复现

保留 request id，便于后续向平台支持反馈。

## AI Agent 生成代码异常

### 代码看起来正确但不能运行

检查 Agent 是否：

- 使用了 Selenium / Playwright 等相似库的 API
- 猜测了不存在的 xbot 方法
- 忽略真实项目中的对象来源
- 没有读取对应文档
- 只做了语法检查，没有进入影刀运行

### 修一个问题又引入多个问题

检查改动范围。优先回到原始版本，重新执行最小修改，不要继续在大规模重构上叠加补丁。

### Agent 一直重复相同方案

应向 Agent提供：

- 上一次执行的精确结果
- 完整异常
- 已经排除的假设
- 新的验证目标

不要只说“还是不行”。

## 错误修正记录

本仓库使用以下入口区分历史错误和未验证结论：

- [错误修正记录](../wiki/error-book.md)
- [待验证事项](../wiki/unresolved.md)

适合写入错误修正记录的内容：

- 旧描述是什么
- 为什么错误
- 正确说法是什么
- 依据是什么
- 哪些文档或代码受影响

## 最小复现模板

```md
# 问题

一句话说明异常。

## 环境

- 影刀版本：
- Windows：
- 浏览器 / Excel / WPS：
- 市场指令版本：

## 输入

填写最小输入。

## 操作步骤

1. ...
2. ...

## 实际结果

粘贴完整错误和返回值。

## 预期结果

说明正确行为。

## 已排除

- ...

## 待验证

- ...
```

## 修复后的验收

- [ ] 原问题可以稳定复现
- [ ] 修复只改了必要内容
- [ ] 最小复现已经通过
- [ ] 原有正常流程没有被破坏
- [ ] 已在影刀环境实际运行
- [ ] 文档中的错误结论已经修正
- [ ] 未验证事项没有写成确定结论
